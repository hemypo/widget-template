# CHANGAN — дизайн-токены проекта

Единый источник истины для всех комплектов проекта `changan/`. Правила использования — раздел 0 `.claude/agents/cefalot-widget-developer.md`: этот блок копируется **дословно** в начало `desktop.css`/`mobile.css` каждого комплекта (для многошаговых форм — один `desktop.css`/`mobile.css` на все шаги комплекта). Ничего не изобретать заново «на глаз» в конкретной форме.

## Статус (создано 2026-08-25)

- Цвета и радиусы взяты напрямую из продакшен-CSS реального сайта `changanauto.ru` (Tailwind-сборка, кастомная палитра `changan-gray-*` / `changan-orange-*` / `changan-blue-main` / `changan-red-main` — извлечено из `build/changan/assets/main-*.css` и `app-*.css`), не придуманы на глаз.
- Шрифт бренда — реальный `ChangAnunitype` (сайт подключает `Light 300 / Regular 400 / Bold 700` через `/fonts/changan/fonts.css`). Файлы `.woff2` скачаны с сайта и лежат в `changan/` рядом с этим документом (`ChangAnunitype-Regular.woff2`, `-Bold.woff2`, `-Light.woff2`).
- **Ключ `{{asset:...}}` для подключения шрифта в CSS — НЕ подтверждён.** У `haval` ключ (`font3`) стал известен только после того, как пользователь вручную залил шрифт в кабинет Cefalot и посмотрел, что подставилось. Для `changan` этого шага ещё не было — при первой заливке в кабинет (`.claude/agents/cefalot-widget-developer.md`, раздел 0 и раздел «Как заливать») нужно загрузить шрифт через кнопку «Шрифт» в редакторе формы и заменить плейсхолдер `{{asset:changan-font-regular}}` ниже на реальный ключ, который подставит кабинет — затем синхронно поправить во всех уже созданных комплектах проекта.
- Акцент один — насыщенный оранжевый `#F89435` (единственный акцентный тон, который реально используется на сайте для CTA/прогресс-баров/бейджей); hover/active — не отдельные токены сайта (Tailwind-палитра даёт только один тон `orange-90` + светлый тинт `orange-30`), потому затемнены вручную по той же методике, что и `haval`.
- Второй, некликабельный акцент — `--cf-blue` (`#224A88`, `changan-blue-main`) — сайт использует его точечно (ссылки/вторичные акценты в тексте), в токен-блок ниже не входит в основной набор, но зафиксирован как опциональный локальный токен на случай, если форме понадобится акцент, отличный от оранжевого CTA.
- **Обновлено (2026-09-03)** — `--cf-accent-glow` (`rgba(248, 148, 53, 0.35)`) перенесён из локального токена конкретных комплектов в канонический блок ниже: по распоряжению пользователя весь проект переведён на «яркий и привлекательный» стиль — градиентные заливки (заголовки, кнопки, чекбоксы, иконка success), свечение (glow-тени) вокруг акцентных элементов, боксовая акцентная стрелка у select с разворотом на фокусе/ховере, подложка-карточка у блока согласий. **Синхронизировано во всех комплектах проекта**, включая киты: `0 - меню` (expanded desktop/mobile; compact-состояние не трогали — там уже был яркий пульсирующий лаунчер и нет текстового заголовка), `00 - спасибо`, `1 - обратный звонок`, `2 - трейд-ин`, `3 - тест-драйв`, `4 - расчет кредита`, `5 - спецпредложения` (все — desktop + mobile), `_kit-forms/`, `_kit-catalog/`. Любой новый комплект копирует этот блок как часть канонического `:root, :host {...}`.
- **Заголовки — капс (2026-09-03)**: `.cefalot-title` (и `.cefalot-substep__title` / `.cefalot-step-title` в каталоге и многошаговых формах) — всегда `text-transform: uppercase` во всех комплектах. Зафиксировано как обязательное правило для любых новых форм проекта.

## Шрифт бренда

Идёт **сразу после** блока `:root, :host` в файле, не перед ним (подтверждённый в кабинете порядок — см. `haval/1 - обратный звонок`, раздел 0b агентского файла).

**Обновлено — ключ подтверждён** (пользователь залил шрифт в кабинет Cefalot через форму `1 - обратный звонок`): семейство теперь называется `ChangAnunitype-Regular` (не просто `ChangAnunitype` — так называется реально подставленный шрифт), только одно начертание подключается через `@font-face` (Bold отдельно не грузили). Ключ **разный для desktop и mobile** — Cefalot выдаёт новый ключ на каждую отдельную заливку через редактор, даже для одного и того же файла (тот же эффект уже наблюдался в `haval`):

```css
/* desktop.css любой формы */
@font-face { font-family: "ChangAnunitype-Regular"; src: url("{{asset:font1}}") format("woff2"); font-display: swap; }
.cefalot-form-custom-template-root { font-family: "ChangAnunitype-Regular", system-ui, sans-serif; }

/* mobile.css любой формы */
@font-face { font-family: "ChangAnunitype-Regular"; src: url("{{asset:font4}}") format("woff2"); font-display: swap; }
.cefalot-form-custom-template-root { font-family: "ChangAnunitype-Regular", system-ui, sans-serif; }
```

Уже синхронизировано (2026-09-02) во всех 5 форм (`1`–`5`), в обоих случаях `--cf-font` тоже переименован на `ChangAnunitype-Regular`.

Для меню (`0 - меню`) — то же правило подключения целится в `.cefalot-custom-template-content`/`-root`, не `-form-...` (раздел 2 агентского файла), но **ключ для меню отдельно НЕ подтверждён** — `font1`/`font4` подтверждены только в контексте формы (заливка через редактор формы), не факт, что тот же ключ подставится в редакторе меню. В `0 - меню` пока стоит плейсхолдер `{{asset:changan-menu-font}}` с явным TODO-комментарием в CSS — замени на реальный ключ после первой заливки шрифта именно в редакторе меню, затем поправь этот документ.

Начертание **Light** (`ChangAnunitype-Light.woff2`) по-прежнему не подключается ни в одном комплекте — файл лежит в `changan/` про запас, как и неиспользуемые `Haval-Light`/`Haval-Medium` в `haval/`.

## Многошаговые формы (desktop-N / mobile-N)

Как в `haval` (см. `.claude/agents/cefalot-widget-developer.md`, подраздел «Многошаговые формы»): несколько основных шагов = несколько полных `desktop-N.html`/`mobile-N.html`, но **один общий** `desktop.css`/`mobile.css` на весь комплект. Применяется в этом проекте к `5 - спецпредложения` — зеркалим структуру `haval` 1:1 (см. распоряжение пользователя «структура точно такая же, как у haval»).

`3 - тест-драйв` и `4 - расчет кредита` — **одношаговые** формы (ровно 4 файла: `desktop.html`, `desktop.css`, `mobile.html`, `mobile.css` каждая), как и одноимённые комплекты `haval/3 - тест-драйв`/`haval/4 - расчет кредита` были пересмотрены с многошаговых на одношаговые — зеркалим актуальную структуру `haval`, а не более раннее предположение о многошаговости.

`2 - трейд-ин` — один HTML-файл на вьюпорт (`desktop.html`/`mobile.html`) с каталожными подшагами внутри (`data-widget-catalog-*`), как в `haval/2 - трейд-ин`.

## Правила применения

1. При создании/правке любого комплекта в `changan/` — канонический блок `:root, :host {...}` копируется в начало `desktop.css` и `mobile.css` (или единственного `desktop.css`/`mobile.css` многошаговой формы) без изменений, сразу после него — строки `@font-face`/`.cefalot-form-custom-template-root {...}` (см. «Шрифт бренда» выше).
2. Локальные, специфичные для одного комплекта переменные заводятся отдельно, с комментарием, что это локальный токен именно этого комплекта — не смешивать с базовым набором.
3. Если значение в этом документе меняется задним числом (в т.ч. когда реальный `{{asset:...}}`-ключ шрифта станет известен) — обновить синхронно все уже существующие комплекты проекта, не оставлять часть форм на старом значении.

## Контентные правила (2026-09-03)

4. Плейсхолдер поля «Имя» — всегда `Введите имя` (не `Иван Иванов` и не другой пример-имя), во всех комплектах проекта, где это поле есть.
5. Поле «Имя» **не включается в мобильную версию** ни одной формы (десктоп — можно, мобайл — нет). При создании нового комплекта с полем «Имя» — в `mobile.html` это поле не добавляется вовсе (не прячется через CSS/hidden, а отсутствует в разметке).
6. Заголовок формы (`.cefalot-title`, а также `.cefalot-substep__title`/`.cefalot-step-title` в каталоге и многошаговых формах) — всегда капсом (`text-transform: uppercase`).
