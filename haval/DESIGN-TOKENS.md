# HAVAL — дизайн-токены проекта

Единый источник истины для всех комплектов проекта `haval/`. Правила использования — раздел 0 `.claude/agents/cefalot-widget-developer.md`: этот блок копируется **дословно** в начало `desktop.css`/`mobile.css` любого комплекта (для многошаговых форм — один `desktop.css`/`mobile.css` на все шаги этого комплекта, см. «Многошаговые формы» ниже). Ничего не изобретай заново на глаз в конкретной форме.

## Статус (обновлено 2026-08-26, hero-layout)

- Источник истины — `haval/1 - обратный звонок/desktop.css` и `mobile.css` (пользователь подтвердил: оба файла отредактированы вручную и на 100% работают как нужно в реальном кабинете). Токен-блок в них дословно совпадает между desktop и mobile.
- Относительно первой версии этого документа изменилось два момента:
  1. **Скругления теперь плоские 5px везде** (`--cf-r-xs/sm/md/pill` все равны `5px`), а не прежняя шкала 4/6/8/999.
  2. **Шрифт бренда подключён по-настоящему** — не то предположение про ключи `{{asset:haval-*}}`, что было в первой версии этого документа. Реальный рабочий вариант ниже, взят прямо из формы 1.
- Формы `1–5` синхронизированы с каноническим набором токенов. Для форм добавлен единый hero-layout: изображение слева на desktop и сверху на mobile; `{{asset:key}}` используется как локальный asset изображения.

## Шрифт бренда (подтверждённое рабочее подключение)

Рабочее подключение шрифта остаётся тем же, но по правилу проекта канонический `:root, :host` должен идти первым в CSS; `@font-face` и системное правило шрифта располагаются сразу после него:

```css
@font-face { font-family: "Haval-Regular"; src: url("{{asset:font3}}") format("woff2"); font-display: swap; }
.cefalot-form-custom-template-root { font-family: "Haval-Regular", system-ui, sans-serif; }
```

Для меню (`0 - меню`) — тот же `@font-face`, но правило подключения целится в `.cefalot-custom-template-content`/`-root`, а не `-form-...` (см. раздел 2 агентского файла про разные классы-обёртки у меню и у формы).

Важно:
- Ключ ассета — `font3` (не `haval-regular`, как ошибочно предполагалось в первой версии этого документа до того, как стало известно реальное значение). Копируй именно `{{asset:font3}}` дословно в новые/дописываемые файлы этого проекта.
- Подключён и используется только один начерк — **Regular**. `Haval-Light.woff2` и `Haval-Medium.woff2` по-прежнему лежат в `haval/` неиспользуемыми — не факт, что это оставлено намеренно; при следующей возможности стоит уточнить у пользователя, планируется ли их подключать (например для `--cf-title`/акцентных начертаний), а не считать это упущением задним числом.

## Многошаговые формы (desktop-N / mobile-N)

Подтверждено пользователем вживую в кабинете, 2026-08-25 (см. `4 - расчет кредита`, `5 - спецпредложения`): форма может состоять из нескольких **основных шагов**, каждый из которых — свой собственный, полный HTML-файл (`desktop-1.html`, `desktop-2.html`, …; аналогично `mobile-1.html`, `mobile-2.html`, …), загружаемый в свой отдельный слот шага в кабинете. Переход между такими шагами — обычные `data-widget-next` (без значения, т.к. следующий загруженный шаг) на последнем элементе шага N и `data-widget-back`/`data-widget-submit` на шаге N+1 — тот же механизм, что и раньше, просто теперь по факту размётан на несколько файлов, а не на один.

**CSS при этом общий на весь комплект, а не на шаг** — один `desktop.css` для всех `desktop-N.html`, один `mobile.css` для всех `mobile-N.html`. Это отдельное, не подтверждённое ранее исключение из «ровно 4 файла на комплект» (раздел 1 агентского файла) — файлов становится `(число шагов десктоп) + (число шагов мобайл) + 1 desktop.css + 1 mobile.css`, а не 4. Канонический токен-блок всё равно копируется дословно в оба CSS-файла, как и раньше.

Это отличается от каталога (`data-widget-catalog-*`, раздел 5 агентского файла, см. `2 - трейд-ин`/`3 - тест-драйв`) — каталог остаётся одним HTML-файлом с подшагами внутри одного шага; схема `desktop-N.html` — это про сами **основные** шаги виджета, а не про подшаги внутри одного из них. Обе схемы можно комбинировать (каталог может быть одним из N основных шагов).

## Правила применения

1. При создании/правке любого комплекта в `haval/` — канонический блок `:root, :host {...}` ставится первым и копируется без изменений в `desktop.css` и `mobile.css`; сразу после него идут `@font-face` и системное правило шрифта.
2. Локальные, специфичные для одного комплекта переменные заводятся отдельно, с комментарием, что это локальный токен именно этого комплекта — не смешивать с базовым набором.
3. Если значение в этом документе меняется задним числом — обновить синхронно все уже существующие комплекты проекта, не оставлять часть форм на старом значении.


## Hero-layout форм

Для форм `1–5` используется единая композиция:
- mobile: hero-изображение сверху, активная часть формы ниже; заголовок, eyebrow и вводный текст находятся поверх hero-изображения (эта часть — `mobile.html`/`mobile.css` — не менялась, источник истины по-прежнему `1 - обратный звонок`);
- изображение подключается только через системный asset `{{asset:key}}`;
- `--cf-hero-image` — локальный токен формы и не входит в канонический `:root, :host`;
- если мобильный сценарий становится слишком длинным, сначала сокращается вертикальная раскладка одинаковых элементов; затем сценарий делится на основные шаги. В `4 - расчет кредита` форма разделена на 3 шага: модель → параметры кредита → контакты.

**Обновлено 2026-09-01, применено ко всем desktop-формам кроме `2 - трейд-ин`** (пользователь явно попросил перенести весь текст с фото в правую часть формы, а не оставлять его наложенным на фото):
- **Desktop-hero — чистое изображение, без текста и без градиентного затемнения.** `.cefalot-hero` больше не содержит `.cefalot-hero__content`, `.cefalot-hero::after`/`--cf-hero-scrim` не используется — только `background-image: url("{{asset:key}}")` во всю колонку.
- **Eyebrow/title/lead переехали в правую панель**, в новый блок `.cefalot-head` — первый элемент внутри `.cefalot-panel`, перед `.cefalot-body`/формой. Стиль текста — тёмный, как обычный текст на белом фоне (не белый поверх фото): `.cefalot-title` — `color: var(--cf-ink)`, `.cefalot-lead` — `color: var(--cf-muted)`, `.cefalot-eyebrow` — плашка `background: var(--cf-accent-light)` / `color: var(--cf-accent-active)` (та же пара токенов, что уже использовалась для `.cefalot-step-eyebrow` в `5 - спецпредложения`). Никаких `text-shadow` — фото под текстом больше нет.
- `.cefalot-head` — `padding-right: calc(var(--cf-tap) + var(--cf-s2))`, чтобы текст не заходил под абсолютно спозиционированный крестик закрытия; в `@media max-width: 900px` (десктоп-бандл на узкой ширине, не путать с `mobile.html`) — `padding-right: 0`.
- **Текстовый блок компактный**: локальный `--cf-fs-title` — `26px` (было `36px`, промежуточно было `28px`); отступ под eyebrow — `var(--cf-s1)`; отступ под title — `var(--cf-s2)`; `.cefalot-lead` — `font-size: 14px`, `line-height: 1.4`. Для форм без lead-текста в hero (шаговый заголовок в `5 - спецпредложения`) — `--cf-fs-title: 22px`.
- В `5 - спецпредложения` (два основных шага, общий `desktop.css`) блок `.cefalot-head` с общим заголовком формы продублирован в начале панели `desktop-1.html` и `desktop-2.html` — так же, как раньше дублировался `.cefalot-hero__content` в обоих файлах — и идёт над специфичным для шага `.cefalot-step-head`.
- Мобильная версия (`@media max-width: 900px` внутри `desktop.css`, отдельно от `mobile.css`) теперь показывает просто картинку сверху (`.cefalot-hero { min-height: 200px }`, без `padding`/текста) и панель с `.cefalot-head` ниже — как и десктоп, без наложения текста на фото.
