# Бриф для Claude Design — виджет Cefalot

Скопируй этот файл целиком в чат с `/design` (Claude Design), заполнив два раздела
«ВХОДНЫЕ ДАННЫЕ» своими значениями. Всё остальное — фиксированные требования платформы,
их менять не нужно.

Результат сохрани в папку `concept/` этого проекта — оттуда его заберёт агент
`cefalot-widget-developer` и соберёт из него итоговые файлы под реальные правила платформы
(снимет обёртку, разложит по слотам CSS, дособерёт паттерн чекбоксов и т.д.). Поэтому концепт
не обязан быть на 100% technically upload-ready — важнее, чтобы были верны контент, компоновка
и стиль, а структурные детали ниже (раздел «Что важно соблюсти уже в концепте») были соблюдены
по возможности, чтобы сократить объём переделки после.

## Контекст платформы

Cefalot — no-code платформа виджетов со своим встроенным парсером и упаковщиком CSS.
Готовый виджет заливается как набор HTML/CSS файлов на отдельные состояния (форма,
разводящее меню, экран «Спасибо», каталог). Платформа сама оборачивает контент в свою
системную разметку и сама обрабатывает клики/навигацию через `data-widget-*` атрибуты —
никакого JS в самих файлах быть не может.

## Что важно соблюсти уже в концепте

- **Никакого `<script>`, `<style>`, `<iframe>`, `<form>`** — используй обычные теги
  (`div`, `header`, `footer`, `p`, `button`, `input`, `select`, `textarea`, безопасный inline SVG).
  Никаких инлайновых `onclick`/`onload`.
- **Чекбоксы — без `<label>`.** Оборачивай чекбокс в `<span>`, а не в `<label>` (на платформе
  `<label>` вокруг чекбокса ломает клики). Рядом с чекбоксом — текст согласия обычным `<span>`.
- **Навигация и отправка — через понятные, явные действия**, а не через `href`/JS: кнопка
  закрытия окна, кнопка отправки формы, переход между шагами, переход к другой форме/каталогу —
  обозначь их как отдельные интерактивные элементы с понятным назначением (агент потом навесит
  на них нужные `data-widget-*` атрибуты).
- **Поля ввода** — стандартные `input`/`select`/`textarea` с явным лейблом текстом (не
  placeholder-only). Для телефона — маска в духе `+7 (999) 999-99-99`.
- **Никаких внешних картинок по `url()`** — иконки только как inline SVG.
- **Не нужно верстать системную обёртку/рамку виджета** — только содержимое конкретного
  состояния (шапка, тело, футер), без фейкового "окна браузера" вокруг.

## Структура по состояниям

- **Разводящее меню** — если у виджета несколько форм, нужен главный экран со списком
  переходов к ним.
- **Экран «Спасибо»** — один общий экран после отправки любой формы: подтверждение +
  дополнительная полезная информация (контакты, время ответа и т.п.). Не делай отдельный
  экран «Спасибо» под каждую форму — он один на весь проект.
- **Каждая форма/каталог** — независимое состояние: десктопная и мобильная версии могут
  визуально отличаться компоновкой (например, боковая рельса на десктопе → горизонтальная
  лента на мобайле), это ожидаемо и нормально.
- **Живые расчёты (калькулятор кредита, трейд-ин и т.п.) на клиенте невозможны** — платформа
  запрещает `<script>`. Такие формы должны собирать параметры и показывать понятный блок
  вида «Точный расчёт пришлём/озвучит менеджер», а не считать реальную цифру в браузере.

## Доступность и UX (сохраняй по умолчанию)

- Размер шрифта в полях ≥ 16px (iOS не зумит при фокусе).
- Тач-цели ≥ 44×44px.
- Видимые лейблы у полей, обязательность — явной звёздочкой.
- Заметное состояние фокуса на интерактивных элементах.
- Мобильная версия — как правило одна колонка, основная кнопка на всю ширину.
